# Code-drawn cinematic animation: reference breakdown and build guide

This is the primary visual-production method for this skill. Build original scenes, characters, props, lighting, diagrams, and motion from **HTML/CSS, SVG, Canvas, or equivalent authored code**. Do not call an image-generation model for artwork, backgrounds, characters, or thumbnails. Screenshotting code-rendered frames for video encoding is rendering, not AI image generation.

## Reconstruct the visual grammar in code

1. **Set and composition.** Use a 16:9 stage (for example SVG `viewBox="0 0 1280 720"`) with stable world coordinates and a common floor baseline. Create a location-specific background, midground, action area and foreground as separate groups. Include enough distinctive props to communicate place, but keep the subject and relevant information readable. Don't force a classroom into unrelated topics.
2. **Character design.** Create original, recurring simplified designs: a readable dark rounded head, independent light eyes and brows, small mouth, slim articulated limbs, a simple clothing silhouette and distinct colors/accessories. Use a family of consistent proportions, not fully rendered realistic people. Characters remain small enough for their surroundings to matter. Keep identity and silhouette consistent, but do not trace, copy or reuse the source characters.
3. **Rig hierarchy.** Use nested SVG `<g>` elements or Canvas transforms: root → body → neck/head → eyes/brows/mouth; root → hips → upper/lower legs → feet; torso → shoulders → upper/lower arms → hands; prop → hand attachment. Position a joint at a local pivot, rotate the child there, then translate back. Keep feet on the same floor during contact; check hand/prop contact and occlusion. A simple rotating segment may need inverse kinematics or corrective keyframes to prevent foot sliding.
4. **Layered visual construction.** Make walls, ground, windows, props and symbols out of named rectangles, paths, ellipses, strokes and groups. Use reusable components and palette tokens; change a prop or diagram without redrawing the whole scene. Do not assemble a sequence of AI-generated stills or replace meaningful action with only camera motion.
5. **Lighting and depth.** Use soft CSS/SVG radial and linear gradients, low-opacity blurred shapes, localized highlights and controlled edge-darkening. Separate warm practical light from cooler ambient areas. Use transparent overlays, gentle shadows and subtle background parallax only when they improve readability. Effects must not dim faces, labels or important props into the background.
6. **Animate purposefully.** Use anticipation → action → hold/reaction → settle, not continuous random wiggles. Establish and maintain eye-line, grounded feet, joint attachments and cause/effect. Integrate writing/diagram reveal with a visible pointing or drawing action. Change props, chart geometry, labels, reactions or framing as the story advances; allow a deliberate hold where it helps comprehension.
7. **Original information design.** Draw and reveal diagram paths, counters, arrows, cards or labels as separate objects. Use short readable labels and reserve the central space for the idea. Only show a board, numbers or a chart when the topic needs it. Cite real factual material and do not present illustrative geometry as a scaled scientific diagram.
8. **Sensible camera.** Default to a stable wide stage. Use selective cuts, a modest push or a detail shot when story meaning changes; do not put a slow zoom on one still for the whole scene. Keep safe margins, avoid cropped heads/feet, and check mobile readability.

## Deterministic animation and export

- Put story beats in a timeline with start/end times, speaker cues and named actions. Implement `render(t)` or `seek(t)` as a pure, deterministic function of seconds: set every animated property from `t`, not accumulated frame deltas or nondeterministic randomness. Use the same function for interactive preview and offline capture.
- For shot-local time `u = t - shotStart`, use eased interpolation between explicit poses. For a walk, animate root translation, alternating legs and arms, body shift, foot contact and a deliberate stop; do not assume a sine-wave alone prevents skating. For writing, animate both the writing reveal and the relevant arm/hand. For counting, animate the actual number and diagram state, then hold the correct result.
- Synthesize the actual narration first when possible using the American-accent, energetic and clear voice directions in `voice-direction.md`. Split at semantic beats and measure audio durations. Fit actions and cuts to the actual voice; a word-count estimate or an SRT alone cannot prove synchronization.
- Render frames from a browser or graphics engine using exact timestamps `t = frame / fps`, then encode with an available video tool such as FFmpeg. Mux voice and appropriately licensed audio separately. A PNG frame sequence or screenshot is a rasterized rendering of the authored vector scene—not generated-image artwork. A playable HTML preview is **not** a finished MP4.
- The included [backyard vector demo](../examples/backyard-vector-demo.html) is a short, original, silent 18-second proof of concept with three stages, a reusable SVG rig and `window.seek(t)`. It is illustrative, not a full story, exact reference reproduction or emergency guidance. [The optional renderer](../examples/render_vector_demo.py) requires Python Playwright, its Chromium browser and FFmpeg with `libx264`; it produces silent MP4 only. Dependencies are not part of the stdlib MCP server. With those optional dependencies already installed, run this from the repository root to render a new file (the renderer will not overwrite it):

```sh
python3 .agents/skills/cinematic-narrative-video/examples/render_vector_demo.py --output backyard-silent-study.mp4
```

Use an environment you are authorized to modify if installation is necessary. The renderer produces no narration or sound, and it cannot automatically assess artistic quality.

## Mandatory quality gate before a full render

1. Build and render a **15–30 second voiced style test** covering an original character walking or interacting with a prop, a meaningful expression/gesture and a visual reveal. Adapt the location and content to the requested niche. The included silent demo is an engineering example, not a substitute for this voiced review.
2. Inspect rendered frames at multiple moments **within each scene**, including before/during/after every action, and play the test if the host can. Check that the body/limbs and scene elements really change, not only the subtitles or camera. Confirm character scale, facial readability, foot/hand contact, lighting, contrast and compositional consistency. Compare against the observed reference characteristics without copying its assets.
3. Listen to the test where possible: speech must be American-accented, energetic, well-projected, clear and aligned; music must not mask it. Mark listening and accent verification as incomplete if they cannot actually be performed. Check labels and captions separately at phone size.
4. If the style is clearly wrong, fix the rig, lighting, staging and motion and rerender. Do not expand a still-image slideshow, awkward rig or low-quality style test into a full-length video. If review or rendering is unavailable, report that limitation and deliver a clearly labeled partial rather than claiming a completed match.
5. Only after the style test passes, build the remaining scenes, render the full video and repeat visual, audio, factual, rights and export checks. Detailed engineering guidance is a starting point; no automatic validator can guarantee visual fidelity or creative quality.
